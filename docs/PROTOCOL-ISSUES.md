## P1 mdns_test 依赖单调时钟推进，Windows 上必挂

- **发现**：2026-10-19，Windows 客户端立项当日跑 `cd protocol && go test .`
- **现象**：`TestMdnsBrowserPrune` 5/5 稳定失败：「过期设备应被淘汰 1 台，实际 0」
- **根因**：测试靠「时间自然流过」让 `time.Since(LastSeen) > 0` 成立，但 Windows
  Go 单调时钟粒度约 0.5ms，测试全程仅数十微秒，`Since` 返回精确 0。Linux
  纳秒级时钟上必过，属平台可移植性缺陷（测试写法，非库逻辑——`Prune` 的
  `> maxAge` 语义本身正确）。
- **建议修法**：测试内显式回拨 `LastSeen`（同包可直接改 map），不赌时钟；
  已在本地工作区按此修（+11 行，test-only），待独立提交
  `fix(protocol): mdns prune 测试适配 Windows 时钟粒度`。

## P2 mDNS TXT `encryption` 枚举缺 DirectLink TCP/TLS 取值

- **发现**：2026-10-19，windows-connection 里程碑设计时
- **现象**：§3.2.1 TXT 表中 `encryption` 只枚举 `"dtls13" / "none"`，而 §7.2
  DirectLink TCP 模式的传输加密是 **TLS 1.3**——现枚举没有能如实声明它的值。
  客户端只能填扩展值 `"tls13"`（字符串字段，消费方不应硬失败）。
- **建议修法**：§3.2.1 表增补 `tls13`（DirectLink TCP/TLS），或把该字段语义
  改为「传输加密能力自由串 + 已知值枚举」。记入下次协议修订。

## P4 §9.1 心跳「收到即回」在双向角色下产生回显放大风暴

- **发现**：2026-10-19，windows-input 里程碑的双进程环回冒烟（间歇性
  「在线但零延迟样本」）
- **现象**：握手完成后心跳帧指数级自增——36 秒实测 **29.5 万帧**（trace 实锤），
  CPU 被回显循环打满，延迟采样/业务帧全部被饿死；是否在观测窗口内恶化
  取决于时序，故表现为间歇性。
- **根因**：§9.1 规定「接收方收到后立即回复 HEARTBEAT」，同时双方又各自
  周期发送（`发送方：每 2 秒发送`）。Role=0x03（双向）时两侧都是发送方 +
  回复方：每收 1 帧回 1 帧，回出去的又被对端回——1:1 无限放大。
- **建议修法**：规范明确二者取一——(a) 心跳由**单侧角色**周期发送、对端
  回复（Host↔Target 语义下成立）；或 (b) 双向各自周期发送、收帧仅作喂狗
  不回帧。客户端已按 (b) 实现。
